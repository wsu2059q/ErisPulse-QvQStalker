# ErisPulse-QvQStalker

**[QvQChat](https://github.com/wsu2059q/ErisPulse-QvQChat) のコンパニオンプラグイン。ボットがグループの普通のメンバーのように、普段はROMしながらどの発言に食いつくかを自分で判断し、誰も話しかけていなくても話したくなったら自分から口を開きます。**

たいていのボットは、メンションされるかプレフィックスを踏まれない限り喋りません。本物のグループの住人は違います。一日中流れを眺めていて、答えられそうな質問があればたまに口を挟み、時には我慢できず自分から話題を振ります。QvQStalker が QvQChat に足すのはこの「後者の振る舞い」です。QvQChat はコマンドフィルタの後・トリガ判定の前に、グループの各メッセージを `qvq.observe` ライフサイクルイベントとしてブロードキャストします。プラグインはこれを受けて、チャットごとに直近メッセージの小さなウィンドウを保持し、話題の熱量を追跡します。メンションにもプレフィックスにも当たらなかったメッセージは、QvQChat がこのプラグインの `qvq_decision` サービスに「返信すべきか」を問い合わせます。加えて、誰にも話しかけられていないときに自分から口を開くかを決める「衝動値」モデルが独立して動きます。

アルゴリズムは QvQChat 3.x の ROM モード（`should_reply` の 5 層判定 + proactive の衝動値モデル）からの移植ですが、あえて QvQChat 本体には入れていません。参加判断は好みがはっきり分かれる挙動で、欲しい人と絶対に要らない人がいるためです。QvQChat パッケージには一切依存しない独立プラグインとして切り出し、`sdk.lifecycle` / `sdk.module.call` / `sdk.storage` の 3 つのフレームワークインターフェースだけでやり取りします。2 つのモジュールはそれぞれ独立にインストール・更新・削除でき、どちらかがいなくても（あるいはバージョンが古くても）もう片方は普通に動きます。

安全はオプションではなく初期状態です。参加判断は、自分で QvQChat の `participation_enabled` スイッチを入れるまでずっと無効です。プラグインが引き起こす発言はすべて QvQChat の SpeechBudget を通ります——グループごとの毎時上限（デフォルト 8 件）、同じグループでのクールダウン（デフォルト 300 秒）、能動発言のグローバルな 1 日上限——のどれもプラグイン側から回避できません。さらにその上に、1 日のクォータ、チャットごとの上限、睡眠時間、反応のないチャットへのクールダウンという自律ブレーキも持ちます。判断のたびに人間が読める `reason` が返るので、Dashboard で「なぜ喋ったのか／なぜ黙っていたのか」を常に確認できます。

## インストール

```bash
epsdk install ErisPulse-QvQStalker
```

または

```bash
pip install ErisPulse-QvQStalker
```

QvQChat と同じ ErisPulse インスタンスに入れてください。ErisPulse >= 2.8.0、Python >= 3.10、そして QvQChat >= 4.0.4（`qvq.observe` イベントと `speak` サービスを提供するバージョン）が必要です。2 つのモジュールが互いを import することはありません。

## 有効化

1. Dashboard の QvQChat 設定ページで参加判断のスイッチ（`participation_enabled`、デフォルトはオフ）を入れます。隣のグループホワイトリストで対象を限定できます（空欄で全グループ）。
2. QvQStalker 自身の設定は同じページの「プラグイン」セクションに現れます。モード・確率・しきい値・睡眠時間はここで調整します。保存した値はロード時に取得され、保存時にもホット適用されるので、ほとんどの変更に再起動は不要です（ウィンドウサイズなど一部はモジュールのロード時に読まれます）。
3. 以上です。以降、ボットがメンションもプレフィックスも拾わなかったグループメッセージは、まず QvQStalker の `qvq_decision` に問い合わせられ、`speak` が返ると QvQChat が返信します。

## 仕組み

### 観測（ROM）

QvQChat はコマンドフィルタの後・トリガ判定の前に、グループの各メッセージについて `qvq.observe` イベントを発火します。ペイロードは純粋なデータ（`chat_key` / `platform` / `sender_id` / `sender_name` / `text` / `is_group` / `at_bot` / `ts` など）で、プラグインは読み取り専用として扱い、イベントを処理済みにしたり例外を投げたりすることは決してありません。各メッセージはチャットごとのリングバッファ（デフォルトで直近 50 件）に入り、4 か所で使われます：熱量計算、沈黙判定、LLM 判断のプロンプト、能動発言の要約です。QvQChat が古くてこのイベントがまだ存在しない場合でもモジュールは普通にロードされ、アップグレードしてリロードすれば届くようになります。

### 話題の熱量

各チャットには 0〜2.0 の熱量値があります。メッセージごとに基本 +0.05、会話が速いほど多く積み上がります：直前のメッセージから 5 秒未満なら +0.15、15 秒未満で +0.08、30 秒未満で +0.03。疑問符は +0.1、感嘆符は +0.05。加算の前に、既存の熱量は静寂の長さに応じて減衰します——静寂 1 分あたり最大半分——ので、冷めた話題は自然に冷えていきます。

### 5 層判定

QvQChat が `qvq_decision(ctx)` を問い合わせたとき、答えは 5 つの層を順に落ちていきます。L1 はコストゼロの正規表現です。メッセージが質問っぽければ——中国語の疑問語（怎么 / 为什么 / 什么 / 是不是 / 吗 / 呢 など）か文末の疑問符——`question_prob` の確率（デフォルト 0.6、話題が熱いとき +0.3、上限 0.95）で参加します。L2 と L3 はそれ自体では何も決めず、「エスカレーションフラグ」を立てるだけです。L2 は熱量が `heat_flag_threshold` を超えたとき、min(熱量×0.3, 0.7) の確率ゲート付きで（生ぬるい話題が毎回昇格しないように）フラグを立て、L3 は最新のメッセージが `silence_threshold_minutes` を超える沈黙を破ったときにフラグを立てます。フラグが立っていて `llm_judge` が有効なら L5 に進みます：直近 10 件のROM記録を添えて、QvQChat のモデルに「この発言、挟むべき？（はい／いいえ）」という単一質問を投げます。タイムアウトは 8 秒で、答えが返らない・解析できない場合は L4 に落ちます。L4 はすべての経路が最終的に着地する確率層です。前回の試みから `min_messages_between_replies` 件以上のメッセージを観測した後、`default_probability` × モード倍率（conservative ×0 / balanced ×1 / active ×2）+ 熱量ボーナスのサイコロを振ります。conservative はサイコロがゼロなので、質問層か LLM 判断からしか喋りません。

結果がどうであれ、戻り値は同じ形で、reason は人間が読める一文です：

```python
{
    "decision": "speak",            # "speak" | "silent"
    "reason": "Question keywords matched (heat 1.24); joining with probability 0.90",
    "score": 0.9,                   # 0 ~ 1
    "urgency": "high",              # "low" | "normal" | "high"
}
```

（reason の文章は中国語と英語の 2 種類を内蔵しています。）

### 衝動値

受け身の発言とは別に、プラグインはチャットごとに半減期 1 時間の「衝動値」を持ちます。チャットが静かなほど薄れていきます。ROM したメッセージ 1 件ごとに、基本 0.06、質問 +0.12、感嘆符 +0.05、長文（20 字以上）+0.04、ボットへのメンション・リプライ +0.15（返したいのに返していないもどかしさ）、さらに少量の熱量ボーナスが積み上がります。バックグラウンドループは約 30 分ごと（×0.7-1.3 のランダムジッター）で目を覚まし、一連のゲートを確認します：睡眠時間、グローバルな 1 日上限、そのチャットで前回口を開いてから `min_silence_hours` 以上経過、衝動値 ≥ `urge_threshold`、チャットごとの 1 日上限、そして未応答クールダウン——前回発言後に誰も反応しなかったチャットでは `unreplied_cooldown_hours` の間黙って我慢します。すべて通れば、その周回で開口するのは 1 回だけ。衝動値が最も高いチャットを選び、直近 10 件のROM記録を文脈として QvQChat の `speak` サービスを呼びます。この呼び出しも QvQChat のバジェットを通ります。サービスがない・失敗する場合は warning を 1 行残し、衝動値を半分にして（毎周リトライしないように）クォータも消費しません。

## 設定

すべての設定は `QvQStalker` モジュール設定配下にあり、QvQChat 設定ページの「プラグイン」セクションで直接編集できます（ErisPulse Dashboard の通常モジュールフォームとしても表示されます）。

| 項目 | デフォルト | 説明 |
|---|---|---|
| `mode` | `balanced` | 参加モード：`conservative`（ランダムな割り込みなし。質問層と LLM 判定のみ発話）/ `balanced` / `active`（基礎確率 2 倍） |
| `default_probability` | `0.03` | balanced モードの基礎参加確率 |
| `question_prob` | `0.6` | 質問っぽいメッセージへの返信確率（熱量 > 0.5 で +0.3、上限 0.95） |
| `min_messages_between_replies` | `15` | 2 回の参加試行の間に観測するメッセージ数（連投防止） |
| `silence_threshold_minutes` | `30` | この分数を超える沈黙を破るメッセージでエスカレーションフラグ |
| `heat_flag_threshold` | `0.8` | 熱量がこの値を超えると（確率ゲート付きで）フラグ |
| `llm_judge` | `false` | フラグが立っているとき、QvQChat のモデルに最終判断を委ねる |
| `judge_model` | 空 | 判断に使うモデル。空なら QvQChat のデフォルト |
| `judge_timeout` | `8.0` | 判断のタイムアウト秒（超えたら確率層へフォールバック） |
| `heat_cap` | `2.0` | 話題熱量の上限 |
| `heat_bonus_cap` | `0.15` | 確率層に上乗せする熱量ボーナスの上限 |
| `sleep_hour` | `2` | 能動発言の就寝時（0-23。`wake_hour` と同じなら制限なし） |
| `wake_hour` | `8` | 能動発言の起床時 |
| `urge_threshold` | `1.0` | 能動発言の資格を得る衝動値 |
| `global_max_per_day` | `3` | 全チャット合計の 1 日能動発言上限 |
| `per_chat_daily` | `1` | チャットごとの 1 日能動発言上限 |
| `unreplied_cooldown_hours` | `12` | 発言後に誰も反応しなかったチャットで黙る時間（時間） |
| `min_silence_hours` | `6` | 同じチャットで前回発言から空けるべき最小時間（時間） |
| `check_interval_minutes` | `30` | 衝動値チェック間隔（分。×0.7-1.3 のジッター付き） |
| `window_size` | `50` | チャットごとに保持するROMメッセージ数（リングバッファ） |

## サービス

| サービス | シグネチャ | 説明 |
|---|---|---|
| `qvq_decision` | `(ctx: dict) -> dict` | QvQChat が問い合わせる参加判断。`{decision, reason, score, urgency}` を返す |
| `group_heat` | `(chat_key: str = '') -> dict` | チャットの話題熱量。`chat_key` 省略時は全チャット |
| `urge_status` | `(chat_key: str = '') -> dict` | 現在の（減衰後の）衝動値としきい値。省略時は全チャット |
| `request_speak` | `(chat_key: str, reason: str = '', prompt: str = '') -> dict` | 指定チャットでの発言を要求。QvQChat のバジェットは通過する |
| `qvq_settings` | `() -> dict` | QvQChat 設定ページの「プラグイン」セクションに表示されるための帰属マーカー |

これらのサービスは QvQChat のエコシステムブリッジを経由して、`eco_QvQStalker_` プレフィックス付きの AI ツールとして自動公開されます。エージェント自身もオーケストレーションも定期タスクも、熱量の確認・衝動値の確認・発言の依頼をコードなしで行えます。
