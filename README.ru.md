# ErisPulse-QvQStalker

**Плагин-компаньон для [QvQChat](https://github.com/wsu2059q/ErisPulse-QvQChat): бот читает группу как живой участник, сам решает, на какое сообщение стоит ответить, и заговаривает первым, даже когда с ним никто не говорит.**

Большинство ботов молчат, пока их не упомянут через @ или не обратятся по префиксу. Живой человек в группе ведёт себя иначе: весь день читает переписку, иногда влезает с ответом, когда спрашивают о том, в чём он разбирается, а порой и сам не выдерживает и завязывает тему. QvQStalker добавляет QvQChat именно это второе поведение. QvQChat рассылает каждое групповое сообщение (после фильтра команд, но до проверки триггеров) событием жизненного цикла `qvq.observe`; плагин держит по каждому чату небольшое окно недавних сообщений и следит за накалом темы. Если сообщение не попало ни в @, ни в префикс, QvQChat спрашивает у сервиса `qvq_decision` этого плагина, стоит ли ответить. Отдельная модель позыва решает, когда боту заговорить самому, без всякого повода.

Алгоритм перенесён из режима подглядывания QvQChat 3.x (пятиуровневая проверка `should_reply` плюс модель позыва из proactive), но намеренно не встроен в QvQChat. Участие в беседе — поведение на любителя: одним оно нужно, другие категорически против. Поэтому это отдельный плагин, вообще не импортирующий пакет QvQChat: всё общение идёт через три интерфейса фреймворка — `sdk.lifecycle`, `sdk.module.call` и `sdk.storage`. Модули можно ставить, обновлять и снимать независимо друг от друга, и каждый спокойно переживает отсутствие или старую версию второго.

Безопасность — состояние по умолчанию, а не опция. Участие выключено, пока вы сами не включите переключатель `participation_enabled` в настройках QvQChat. Каждый ответ, инициированный плагином, всё равно проходит через SpeechBudget QvQChat — лимит на группу в час (по умолчанию 8), кулдаун в группе (по умолчанию 300 секунд) и глобальный дневной лимит самостоятельных реплик — и обойти его плагин не может. Поверх этого у него собственные тормоза: дневные квоты, лимиты на чат, «часы сна» и кулдаун для чатов, где на реплику бота никто не отозвался. Каждое решение возвращает человекочитаемый `reason`, так что в Dashboard всегда видно, почему бот заговорил — или почему промолчал.

## Установка

```bash
epsdk install ErisPulse-QvQStalker
```

или

```bash
pip install ErisPulse-QvQStalker
```

Ставьте в тот же экземпляр ErisPulse, где стоит QvQChat. Нужны ErisPulse >= 2.8.0, Python >= 3.10 и QvQChat >= 4.0.4 (версия, в которой есть событие `qvq.observe` и сервис `speak`). Модули друг друга не импортируют.

## Включение

1. Откройте страницу настроек QvQChat в Dashboard и включите участие (переключатель `participation_enabled`, по умолчанию выключен). Рядом белый список групп ограничивает, где участие работает; пусто — все группы.
2. Настройки самого QvQStalker появляются в разделе «Плагины» той же страницы: режим, вероятности, пороги, часы сна. Сохранённые значения забираются при загрузке и применяются на лету при сохранении, так что большинству изменений перезапуск не нужен (пара штук вроде размера окна читается при загрузке модуля).
3. На этом всё. Дальше любое групповое сообщение без @ и без префикса сначала попадает на `qvq_decision` плагина; если он ответил `speak`, QvQChat отвечает в группу.

## Как это работает

### Наблюдение

QvQChat рассылает событие `qvq.observe` для каждого группового сообщения после фильтра команд и до проверки триггеров. Полезная нагрузка — чистые данные (`chat_key`, `platform`, `sender_id`, `sender_name`, `text`, `is_group`, `at_bot`, `ts`, ...); плагин только читает их, никогда не помечает событие обработанным и не бросает исключений. Каждое сообщение попадает в кольцевой буфер на чат (по умолчанию последние 50) и дальше работает в четырёх местах: счётчик накала, проверка тишины, промпт для LLM-судьи и контекст самостоятельной реплики. Если событие в старом QvQChat ещё нет, модуль всё равно загрузится — просто ничего не будет получать, пока вы не обновитесь и не перезагрузите его.

### Накал темы

У каждого чата есть значение накала от 0 до 2.0. Каждое сообщение добавляет базовые 0.05, и тем больше, чем быстрее идёт разговор: сообщение спустя менее 5 секунд после предыдущего даёт +0.15, менее 15 секунд — +0.08, менее 30 секунд — +0.03. Вопросительный знак добавляет 0.1, восклицательный — 0.05. Перед прибавлением старое значение затухает пропорционально паузе — максимум вдвое за полную минуту тишины, — так что остывшая тема остывает сама.

### Пятиуровневое решение

Когда QvQChat вызывает `qvq_decision(ctx)`, ответ проходит пять уровней. L1 — бесплатное регулярное выражение: сообщение, похожее на вопрос — китайские вопросительные слова (怎么 / 为什么 / 什么 / 是不是 / 吗 / 呢 ...) или вопросительный знак в конце — вступает с вероятностью `question_prob`, по умолчанию 0.6, +0.3 при горячей теме, но не больше 0.95. L2 и L3 сами ничего не решают — они поднимают «флаг эскалации». L2 поднимает его, когда накал превысил `heat_flag_threshold`, с вероятностным затвором min(накал×0.3, 0.7), чтобы едва тёплая тема не эскалировала каждый раз; L3 — когда новое сообщение прерывает тишину длиннее `silence_threshold_minutes`. Если флаг поднят и включён `llm_judge`, вступает L5: плагин даёт модели QvQChat последние 10 подслушанных сообщений и задаёт один вопрос — «стоит ли влезть с репликой?» — с таймаутом 8 секунд; нет ответа или нечитаемый ответ — падаем на L4. L4 — вероятностный этаж, на который в итоге падает всё: после как минимум `min_messages_between_replies` наблюдённых сообщений с прошлой попытки бросается кубик `default_probability` × множитель режима (conservative ×0, balanced ×1, active ×2) плюс бонус за накал. В conservative кубик равен нулю, так что бот заговорит только через слой вопросов или через LLM-судью.

Каким бы ни был исход, возвращается одно и то же — с reason, который можно прочитать человеку:

```python
{
    "decision": "speak",            # "speak" | "silent"
    "reason": "Question keywords matched (heat 1.24); joining with probability 0.90",
    "score": 0.9,                   # 0 ~ 1
    "urgency": "high",              # "low" | "normal" | "high"
}
```

(Шаблоны reason встроены на китайском и английском.)

### Позыв

Помимо реакций, плагин ведёт по каждому чату позыв (urge) с периодом полураспада 1 час — чем дольше в чате тишина, тем сильнее он выветривается. Каждое подслушанное сообщение добавляет: базовые 0.06, вопрос +0.12, восклицание +0.05, длинное сообщение (от 20 знаков) +0.04, упоминание или ответ боту +0.15 (зуд «хочу ответить, но не отвечаю»), плюс небольшой бонус за накал. Фоновый цикл просыпается примерно раз в 30 минут (со случайным джиттером ×0.7-1.3) и проходит цепочку затворов: часы сна, глобальный дневной лимит, с последней реплики в этом чате прошло не меньше `min_silence_hours`, позыв ≥ `urge_threshold`, дневной лимит на чат и кулдаун безответности — если после реплики бота в чате ни звука, он молчит ещё `unreplied_cooldown_hours`. Когда всё пройдено, за раунд звучит ровно одна реплика — в чате с самым высоким позывом; вызывается сервис `speak` QvQChat, а контекстом служат последние 10 подслушанных сообщений. Вызов по-прежнему проходит через бюджет QvQChat; если сервиса нет или он упал, плагин пишет warning, ополовинивает позыв (чтобы не долбить ретраями каждый раунд) и не тратит квоту.

## Настройки

Все параметры живут в конфигурации модуля `QvQStalker` и редактируются в разделе «Плагины» страницы настроек QvQChat (и одновременно выглядят обычной формой модуля в Dashboard ErisPulse).

| Параметр | По умолчанию | Описание |
|---|---|---|
| `mode` | `balanced` | Режим участия: `conservative` (никаких случайных реплик; говорится только через слой вопросов и LLM-судью) / `balanced` / `active` (базовая вероятность удвоена) |
| `default_probability` | `0.03` | Базовая вероятность вступления для режима balanced |
| `question_prob` | `0.6` | Вероятность ответа на похожее на вопрос сообщение (+0.3 при накале > 0.5, потолок 0.95) |
| `min_messages_between_replies` | `15` | Сколько сообщений наблюдать между двумя попытками вступить (антифлуд) |
| `silence_threshold_minutes` | `30` | Сообщение, прерывающее тишину дольше этого, поднимает флаг |
| `heat_flag_threshold` | `0.8` | Накал выше этого значения (с вероятностным затвором) поднимает флаг |
| `llm_judge` | `false` | Поручить модели QvQChat решающее «да/нет», когда поднят флаг |
| `judge_model` | пусто | Модель для судьи; пусто = модель QvQChat по умолчанию |
| `judge_timeout` | `8.0` | Таймаут судьи в секундах (по истечении — на вероятностный уровень) |
| `heat_cap` | `2.0` | Максимум накала темы |
| `heat_bonus_cap` | `0.15` | Максимум бонуса за накал в вероятностном уровне |
| `sleep_hour` | `2` | Час отхода ко сну (0-23; равен `wake_hour` — расписание отключено) |
| `wake_hour` | `8` | Час подъёма |
| `urge_threshold` | `1.0` | Позыв, дающий чату право на самостоятельную реплику |
| `global_max_per_day` | `3` | Дневной лимит самостоятельных реплик по всем чатам |
| `per_chat_daily` | `1` | Дневной лимит самостоятельных реплик на чат |
| `unreplied_cooldown_hours` | `12` | Сколько часов молчать в чате, где после реплики бота не было ни одного сообщения |
| `min_silence_hours` | `6` | Минимум часов с последней самостоятельной реплики в том же чате |
| `check_interval_minutes` | `30` | Интервал проверки позыва в минутах (× случайный джиттер 0.7-1.3) |
| `window_size` | `50` | Сколько подслушанных сообщений хранить на чат (кольцевой буфер) |

## Сервисы

| Сервис | Сигнатура | Описание |
|---|---|---|
| `qvq_decision` | `(ctx: dict) -> dict` | Решение об участии, которое запрашивает QvQChat; возвращает `{decision, reason, score, urgency}` |
| `group_heat` | `(chat_key: str = '') -> dict` | Накал темы одного чата; без `chat_key` — всех чатов |
| `urge_status` | `(chat_key: str = '') -> dict` | Текущий (с учётом распада) позыв и порог одного чата или всех |
| `request_speak` | `(chat_key: str, reason: str = '', prompt: str = '') -> dict` | Попросить бота заговорить в чате; всё равно проходит бюджет QvQChat |
| `qvq_settings` | `() -> dict` | Маркер принадлежности: благодаря ему плагин виден в настройках QvQChat |

Через экосистемный мост QvQChat эти сервисы автоматически открываются агенту как AI-инструменты (с префиксом `eco_QvQStalker_`), так что сам бот, сценарии оркестрации и задачи по расписанию могут смотреть накал, проверять позыв и просить реплику без единой строчки кода.
